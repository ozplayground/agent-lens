# Intent: 디자인시스템과 반응형 UI/UX 재설계

Author: wonyoung choi (요청), Claude (정리)
Status: accepted
Approved-by: 자동 승인 (Claude) (2026-11-06)
Source: 아이디어 (2026-11-06 대화 요청)

## 문제
원작성자의 말: "지금 전체적으로 디자인이 너무 별로야, pc 모바일 태블릿등에서 사용성이 좋은 ui ux가 필요해, 디자인시스템을 설계하고 ui ux를 수정해줘"

2026-11-06 에 로컬에서 띄운 화면(1440×900, 820×1180, 390×844)과 `docs/ui-spec.md`, `docs/functional-spec/07-ui-common.md`, `docs/known-issues.md` 'UI·접근성' 절에서 확인한 증거:
- 헤더 버튼 9~10개(AI 챗, 소스 & 리서처, MCP, RSS, 공유 & 알림, 다음 수집, 초기화 & 재수집, 즉시 수집, ⌘K, 테마)가 1440px 에서도 두 줄로 넘친다. 390px 에서는 헤더가 약 170px 를 차지한다.
- 뉴스 피드 첫 화면에 기사 전에 띠가 5개(브리핑 배너, 피드 소개, Tech Radar, 카테고리 탭, 소스 필터·검색·정렬) 쌓인다. 1440px 에서 첫 카드가 y≈625 에서 시작하고, 390px 첫 화면에는 기사가 하나도 보이지 않는다.
- 390px 에서 정렬 버튼 글자가 두 줄로 깨지고("인기\n순"), 소스 pill·카테고리 탭은 가로로 잘린다.
- 파괴적 동작 "초기화 & 재수집" 이 헤더 주요 버튼 옆에 빨간 버튼으로 놓여 있다.
- 디자인 기준이 없다. 컴포넌트가 다크 테마 hex 값(`bg-[#0d1117]`, `text-[#8b949e]` 등)과 Tailwind 팔레트(`slate-*`, `blue-*` 등, 46개 파일에 약 1,750곳)를 직접 쓰고, 테마는 `globals.css` 의 `html:not(.dark) …` / `html.dark …` `!important` 덮어쓰기 약 250줄로 바꾼다. `@custom-variant dark` 가 없어 `dark:` 유틸리티는 앱 테마가 아니라 OS 설정을 따른다.
- 글꼴이 섞여 있다: 라벨·배지에 고정폭 글꼴과 영문 대문자 제목("3-BULLET EXECUTIVE TL;DR"), 본문은 시스템 글꼴. Geist 글꼴은 읽기만 하고 쓰지 않는다.
- 접근성: `/` 에서 Enter·Space 를 항상 `preventDefault()` 해 포커스된 버튼을 키보드로 누를 수 없다. 모달이 열려 있어도 j/k/b/c/t 가 뒤 피드에 먹고 Escape 가 모든 모달을 한꺼번에 닫는다. 대부분 모달에 `role="dialog"`·aria 라벨·포커스 트랩이 없다. 뷰포트 확대를 막았다.
- `animate-in` 류 클래스를 쓰지만 정의가 없어 애니메이션이 동작하지 않는다.
- 640px 미만에서 스케줄 버튼, 1024px 미만에서 챗 헤더 '새 대화' 버튼이 사라진다. `/chat` 에서는 테마를 바꿀 수 없다. 헤더 버전 배지는 `v0.1.0` 고정(실제 0.3.1).
- frontend eslint 가 이미 22개 파일에서 오류 54개로 실패해 `make check` 가 통과하지 않는다 (2026-11-06 측정).

## 기대 결과
- 디자인시스템: 색·글꼴·크기·간격·반경·그림자·모션·z-index 를 토큰으로 정의하고, 라이트·다크 두 테마를 토큰 값만 바꿔 적용한다. 공통 UI 부품(버튼, 아이콘 버튼, 입력, 배지, 탭, 칩, 카드, 대화상자/시트, 메뉴, 빈·로딩·오류 상태 등)을 한 곳에 둔다. 문서로 남긴다.
- 측정 기준:
  1. `frontend/src/**/*.tsx` 에 임의 hex 색 클래스(`-[#xxxxxx]`)가 0개, `globals.css` 에 `!important` 테마 덮어쓰기가 0개.
  2. 앱 테마(light/dark/system)를 바꾸면 `dark:` 를 포함한 모든 요소가 같은 테마로 그려진다.
  3. 360, 390, 768, 1024, 1440px 폭에서 가로 스크롤이 없다.
  4. 모든 폭에서 상단 헤더 높이가 64px 이하이고 한 줄이다.
  5. 390×844 첫 화면에 기사 카드 제목이 1개 이상 보인다. 1440×900 첫 화면에 기사 카드가 한 줄 이상 보인다.
  6. 모바일(<768px)에서 주요 조작 요소의 터치 영역이 44×44px 이상이다.
  7. 모달·시트가 `role="dialog"`, `aria-modal`, 제목 연결, 포커스 트랩, 닫을 때 포커스 복귀를 갖고, Escape 는 맨 위 하나만 닫는다. 모달이 열려 있으면 피드 단축키가 동작하지 않는다. 포커스된 버튼을 Enter·Space 로 누를 수 있다.
  8. 뷰포트 확대를 막지 않는다.
  9. 기존 기능(`docs/functional-spec/` 의 NEWS, CHAT, BRF, SRC, MCP, UI 화면 기능)이 하나도 빠지지 않고 각 폭에서 닿을 수 있다.
  10. `make check` 의 frontend 단계(vitest, eslint, `tsc --noEmit`)가 통과한다.

## 영향받는 사용자와 시스템
- 웹 UI 사용자: 뉴스 피드(`/`), AI 챗(`/chat`), 모든 모달(기사 상세, 브리핑, 공유 & 알림 설정, 소스 & 리서처, MCP, 스케줄, 커맨드 팔레트)
- frontend: `frontend/src/app/**`, `frontend/src/components/**`, `frontend/src/context/**`, `frontend/src/hooks/**`, `frontend/src/tests/**`
- 문서: `docs/ui-spec.md`, `docs/functional-spec/07-ui-common.md`, 관련 기능명세, `docs/known-issues.md` 'UI·접근성' 절, 새 디자인시스템 문서
- backend: 바뀌지 않는다

## 제약
- backend, REST API, SSE 계약, `frontend/src/types/**`·`frontend/src/mocks/**` 의 스키마·응답 형태는 바꾸지 않는다. 화면만 바꾼다.
- 스택은 그대로: Next.js 16, React 19, Tailwind CSS 4, lucide-react. 무거운 UI 라이브러리(컴포넌트 킷, CSS-in-JS)를 추가하지 않는다. 외부 폰트·CDN 에 런타임 의존하지 않는다.
- 기능을 없애지 않는다. 자리를 옮기거나 메뉴로 묶는 것은 된다.
- UI 문구는 한국어를 유지한다. 테스트가 찾는 라벨·aria 이름은 되도록 유지하고, 바뀐 화면 구조 때문에 테스트를 고쳐야 하면 그 이유를 plan 에 적는다.
- 사용자의 localStorage 데이터(테마, 북마크, 챗 세션)를 잃지 않는다. 키 이름과 형식을 바꾸지 않는다.
- 한 번에 바꾸는 범위가 크다. 화면 단위로 나눠 단계마다 검사를 통과시킨다.
- 하네스 역할을 지킨다: spec 은 spec-writer, plan 은 planner, 구현은 implementer, 검증 판정은 verifier, 리뷰는 reviewer 서브에이전트가 한다.

## 열린 질문
원작성자가 "스스로 판단해서 완료" 하라고 위임했으므로, 아래는 spec 에서 정하고 근거를 남긴다.
- 브랜드 색과 전체 인상(지금의 GitHub 다크 계열을 이어갈지, 중립 회색 + 단일 강조색으로 갈지)
- 헤더 정보 구조: 어떤 동작을 헤더에 남기고, 어떤 것을 "더보기" 메뉴·커맨드 팔레트·설정으로 옮길지. 모바일 하단 내비게이션을 둘지
- 피드 첫 화면 구성: 브리핑 배너·피드 소개·Tech Radar 를 접거나 합칠지, 필터를 sticky 툴바로 둘지
- 모달의 모바일 표현: 전체 화면 시트로 바꿀지
- 태블릿(768~1023px)에서 챗 사이드바를 드로어로 둘지 고정할지
- lint 기준선 오류 54개 중 `types/**`·`mocks/**`·`lib/**` 에 있는 것을 어떻게 고칠지 (타입 표기만 고치고 계약은 그대로 둘 수 있는지)
- 바뀐 화면을 검증하는 방법: 단위 테스트 외에 폭별 스크린샷 확인을 어떻게 남길지
