## 1. 프로덕트 비전 및 문제 정의 (Problem Statement & Vision)
- **배경 (Background)**: 생성형 AI 기술이 자율 에이전트(Autonomous Agent), 엔지니어링 하네스(Engineering Harness), MCP(Model Context Protocol) 생태계로 빠르게 진화함에 따라, 엔지니어와 리서처에게는 노이즈가 제거된 고신호 기술 큐레이션과 원본 문서 기반의 심층 대화형 분석 환경이 요구됨.
- **문제 정의 (Problem Statement)**:
  1. 기존 뉴스 피드의 표면적 요약으로는 실무 아키텍처 시사점(`Why It Matters`)과 핵심 기술 스택을 파악하기 어려움.
  2. 단일 LLM 종속 구조로는 조직별 다양한 인프라 요구사항을 충족하기 어렵고, 대화 중 질의 난이도에 따라 모델 티어를 직관적으로 전환하기 불편함.
  3. 클라이언트 사이드 API 키 노출이나 형상관리 커밋 실수로 인한 보안 유출 위험을 원천 차단해야 함.
- **프로덕트 비전 (Vision)**: 멀티 프로바이더 LLM(Anthropic Claude, Google Gemini, OpenAI, OpenAI-Compatible / Ollama) 기반의 고신호 기술 큐레이션과 상단 헤더·입력창 듀얼 배치 멀티 모델 셀렉터, 그리고 기업급 Zero-Leak 보안을 갖춘 에이전틱 리서치 워크스페이스 제공.

## 2. 타깃 페르소나 및 유저 저니 맵 (Personas & User Journey)

### 2.1 대표 페르소나
- **페르소나명**: 박에이전트 (31세, AI 에이전트 플랫폼 리드 엔지니어 & 시스템 아키텍트)
- **주요 목표**: 매일 수집되는 AI 에이전트·하네스·MCP 소식에서 핵심 엔지니어링 시사점을 신속히 파악하고, 질의 목적에 맞는 최적의 LLM 모델을 선택해 심층 아키텍처 리포트 및 구현 코드를 도출함.
- **핵심 페인포인트**: 피상적인 2줄 요약의 한계, 불명확한 모델 선택 동선 및 대화 중 모델 변경 시 맥락 유실, API 키 유출에 대한 보안 우려.

## 5. 비기능적 요구사항 (Non-Functional Requirements)
- **성능 (Performance)**: 주요 화면 첫 렌더링(LCP) 1.5초 이내, SSE 진행 상태 첫 이벤트(`event: status`) 수신 200ms 이하, 경량 모델(Haiku/Flash 등) TTFT 300ms 이하 및 균형 모델(Sonnet 등) TTFT 600ms 이하 달성.
- **보안 (Security)**: 클라이언트 번들 내 LLM API 키 포함을 전면 금지하고 백엔드 환경변수(`.env`) 격리 및 서버 사이드 SSE 프록시 스트리밍을 강제하며, 관리자 UI에서는 키 마스킹 표시만 허용.
- **호환성 및 확장성 (Compatibility & Extensibility)**: 멀티 프로바이더(Anthropic Claude, Google Gemini, OpenAI, OpenAI-Compatible / Ollama) 플러그형 인터페이스 준수 및 모바일(375px~), 태블릿, 데스크톱 반응형 레이아웃과 다크 모드 완벽 지원.
