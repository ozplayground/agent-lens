### [FUNC-FEED-001] 다차원 피드 필터링 및 카드 목록 조회

#### 1. 기본 정보
- **기능명**: 다차원 카테고리/출처/고신호 필터링 및 피드 카드 목록 조회
- **기능 ID**: `FUNC-FEED-001`
- **대응 요구사항 ID**: `REQ-FEED-001`
- **대상 화면 코드**: `SCR-FEED-001` (메인 피드 화면)
- **우선순위**: Must Have
- **관련 액터 (Actor)**: 일반 엔지니어 / AI 연구원

#### 2. 사전 조건 (Pre-conditions)
1. 사용자가 메인 웹 대시보드(`SCR-FEED-001`)에 정상 진입한 상태.
2. 백엔드 뉴스 조회 API가 정상 가동 중인 상태.

#### 3. 사용자 인터랙션 및 시스템 동작 흐름과 플로우차트 (Step-by-Step Flow & Flowchart)
1. 사용자가 상단 카테고리 버튼(`harness`, `mcp_plugins_skills`, `agent_tech`, `ai_news`, `all`), 출처 탭(GitHub, ArXiv, GeekNews 등), 또는 "⭐️ Must Read Only" 토글 스위치를 클릭한다.
2. 정렬 옵션 드롭다운에서 `hot`(추천순), `latest`(최신순), `quality`(품질점수순) 중 하나를 선택한다.
3. 클라이언트는 선택 상태를 갱신하고 현재 페이지를 1페이지로 초기화한다.
4. 클라이언트는 비동기 API 요청을 전송하고 카드 그리드 영역에 스켈레톤 로더를 노출한다.
5. 서버 응답 수신 시 스켈레톤을 해제하고 18개의 뉴스 카드를 그리드로 렌더링한다. 데이터가 0건인 경우 Empty State를 렌더링한다.

```mermaid
flowchart TD
    A[사용자 필터/정렬 옵션 선택] --> B[선택 상태 갱신 & Page=1 초기화]
    B --> C[API 요청 전송 및 스켈레톤 UI 표시]
    C --> D{서버 응답 결과}
    D -- 성공 & 데이터 >= 1 --> E[18개 카드 그리드 렌더링]
    D -- 성공 & 데이터 = 0 --> F[Empty State 및 필터 초기화 안내]
    D -- 오류 또는 네트워크 지연 --> G[에러 배너 노출 및 재시도 버튼 활성화]
```

#### 5. 비즈니스 규칙 (Business Rules)
- **BR-FEED-001-1 (하이 시그널 판정 기준)**: `is_high_signal` 플래그는 `quality_score >= 7.8` 조건을 만족하는 아티클에 부여되며, UI 카드 상단에 노란색 별표 배지로 강조 표시된다.
- **BR-FEED-001-2 (기본 정렬 공식)**: `sort=hot`인 경우 `hotness_score DESC, published_at DESC` 복합 정렬을 적용한다.
- **BR-FEED-001-3 (페이지네이션 단위)**: 1페이지당 노출 카드 수는 18개(`size=18`)로 고정하며, 총 아티클 수가 18개 이하일 경우 페이지네이션 바를 숨긴다.
- **BR-FEED-001-4 (카드 직접 챗 핸드오버)**: 카드 우측 하단 또는 호버 시 노출되는 'Ask AI' 버튼을 클릭하면 상세 모달 팝업 과정을 건너뛰고 대상 기사 컨텍스트(`sourceId`)를 장착한 채 독립 전용 AI 챗(`/chat?sourceId={id}`)으로 직접 전환된다.

- **기능 ID**: `FUNC-FEED-002`

- **대상 화면 코드**: `SCR-FEED-001` (메인 피드 상단 검색바)
- **우선순위**: Must Have

3. 입력값이 2자 이상인 경우 시스템은 자동으로 검색 질의를 서버로 전송한다.

```mermaid

    B -- 0자 (초기화) --> C[검색 조건 해제 & 전체 피드 복귀]
    B -- 1자 --> D[입력 대기 (검색 미트리거)]

    F --> G[검색 결과 매칭 카드 렌더링]
```

1. 피드 카드 목록에서 특정 아티클 카드를 클릭한 상태.

### [FUNC-FEED-007] 파워 유저 키보드 단축키(j/k 탐색, /, b, c) 및 피드 포커스 내비게이션

#### 1. 기본 정보
- **기능명**: 파워 유저 키보드 단축키(j/k 탐색, /, b 북마크, c 챗 핸드오버) 및 피드 포커스 내비게이션
- **기능 ID**: `FUNC-FEED-007`
- **대응 요구사항 ID**: `REQ-SHORTCUT-001`, `REQ-FEED-001`, `REQ-CHAT-002`
- **대상 화면 코드**: `SCR-FEED-001` (메인 피드 화면)
- **우선순위**: Must Have
- **관련 액터 (Actor)**: 파워 유저 엔지니어, AI 연구원

#### 2. 사전 조건 (Pre-conditions)
1. 메인 피드(`SCR-FEED-001`)에 1개 이상의 뉴스 카드 아이템이 렌더링된 상태.
2. 사용자의 포커스가 검색창 등 텍스트 입력 엘리먼트 외부에 위치한 상태.

#### 3. 사용자 인터랙션 및 시스템 동작 흐름과 플로우차트 (Step-by-Step Flow & Flowchart)
1. 사용자가 메인 피드 화면에서 `j` 키를 누르면 첫 번째 또는 다음 뉴스 카드로 포커스 인덱스가 1 증가하며 파란색 포커스 링(`ring-2 ring-blue-500`)이 활성화된다.
2. 사용자가 `k` 키를 누르면 이전 뉴스 카드로 포커스 인덱스가 1 감소한다.
3. 포커스된 카드가 브라우저 화면 밖으로 벗어난 경우, 시스템은 카드가 시야에 들어오도록 부드럽게 자동 스크롤(`scrollIntoView({ block: 'nearest' })`)한다.
4. 카드가 선택된 상태에서 사용자가 액션 키를 누르면 다음 동작이 수행된다:
   - `Enter` 또는 `Space`: 포커스된 카드의 상세 모달(`SCR-FEED-002`)을 즉시 오픈한다.
   - `c`: 대상 기사 컨텍스트를 장착한 채 전용 챗(`/chat?sourceId={id}`)으로 즉시 핸드오버한다.
   - `b`: 대상 기사의 북마크 보관 상태를 즉시 토글하고 토스트 메시지를 표시한다.
5. 화면 어느 곳에서든 `/` 키를 누르면 상단 검색창으로 포커스가 이동하며 검색어를 즉시 타이핑할 수 있도록 준비된다.

```mermaid
flowchart TD
    A[메인 피드 화면에서 키보드 입력] --> B{텍스트 입력창 포커스 여부}
    B -- 입력창 포커스 중 --> C[기본 타이핑 동작 수행 & 단축키 차단]
    B -- 피드 본문 포커스 --> D{입력된 단축키 판별}
    D -- j 키 --> E[포커스 인덱스 +1 & 대상 카드로 스크롤 이동]
    D -- k 키 --> F[포커스 인덱스 -1 & 대상 카드로 스크롤 이동]
    D -- Enter 키 --> G[선택된 기사 상세 모달 팝업 오픈]
    D -- c 키 --> H[선택 기사 Scoped 전용 챗 /chat?sourceId=id 핸드오버]
    D -- b 키 --> I[선택 기사 북마크 토글 & 토스트 노출]
    D -- / 키 --> J[상단 검색바 포커스 이동 & e.preventDefault]
```

#### 5. 비즈니스 규칙 (Business Rules)
- **BR-FEED-007-1 (경계값 인덱스 래핑 차단)**: `j` 키를 눌러 현재 페이지의 마지막 카드(18번째)에 도달했을 때 인덱스는 더 이상 증가하지 않고 마지막 카드를 유지하며, `k` 키를 눌러 첫 번째 카드에 도달했을 때도 0 이하로 내려가지 않는다.
- **BR-FEED-007-2 (브라우저 기본 스크롤 동작 방지 - preventDefault)**: `j`, `k`, `/` 키 입력 시 브라우저 기본 페이지 스크롤 및 브라우저 내장 빠른 검색 창이 뜨지 않도록 `e.preventDefault()`를 강제 적용한다.
- **BR-FEED-007-3 (선택 없는 상태에서의 액션 가드)**: 카드가 아무것도 포커스되지 않은 상태(`focused_card_index === -1`)에서 `Enter`, `c`, `b` 키가 입력되면 동작을 무시하고, `j` 키를 먼저 누르도록 시각적 포커스 힌트를 제공한다.
