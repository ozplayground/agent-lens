# research-product — 출처 없는 주장은 발견에 넣지 않는다

## 범위와 기록 위치
- 첫 인자가 `docs/features/` 아래 기능 id 이면 기능 조사다. 그 기능의 `research.md` 에 [템플릿](template.md) 절을 쓴다 (있으면 고친다).
- 아니면 제품 전체 조사다. `docs/research/product.md` 에 쓴다. 이미 있으면 질문과 발견을 이어서 번호를 붙여 추가한다. 지우지 않는다.

## 절차
1. 조사 질문을 정한다. `$ARGUMENTS` 에 있으면 그것을 쓴다. 없으면 기능 intent.md 의 열린 질문이나 `docs/product.md` 의 비어 있는 절에서 고른다.
2. 질문을 서로 독립인 관점으로 나눈다 (예: 경쟁 제품, 대상 사용자와 요구, 가격·시장). 관점마다 `researcher` 서브에이전트를 병렬로 부른다.
   - 넘길 것: 관점, 질문, 이미 아는 사실 (product.md, intent 요약)
   - 돌려받을 것: 주장마다 출처 URL·확인일·신뢰도가 붙은 발견 목록, 제품 벤치마크 행
3. 발견을 합친 뒤 다른 `researcher` 인스턴스에 교차 확인을 맡긴다. 반박된 주장은 버리고, 단일 출처는 신뢰도 '낮음' 으로 남긴다.
4. 템플릿대로 쓴다. 다 채웠으면 `Status: complete`.
5. '시사점' 을 연결하라고 알린다: 제품 전체 조사면 `docs/product.md` 의 범위·원칙, 기능 조사면 intent.md 의 열린 질문. 산출물의 승인 상태는 바꾸지 않는다.

## 더 깊은 조사
출처 수십 개를 교차 검증하는 보고서가 필요하면 사용자에게 내장 워크플로 `/deep-research <질문>` 실행을 제안한다 (사용자가 직접 실행할 때만 돈다). 결과는 '발견' 에 출처와 함께 옮긴다.

## 하지 않는 것
- 출처 없는 숫자·주장 기록
- 기술 후보 비교 (`/research-tech`)
- 소스 코드 편집, 산출물 Status 변경
