# research-tech — 문서 조사는 출처로, 성능은 같은 조건에서 잰 숫자로만 쓴다

## 범위와 기록 위치
- 첫 인자가 `docs/features/` 아래 기능 id 이면 기능 조사다. 그 기능의 `research.md` 에 [템플릿](template.md) 절을 쓴다 (있으면 고친다).
- 아니면 시스템 전체의 기술 선택이다. `docs/research/tech.md` 에 쓴다. 이미 있으면 번호를 이어서 추가한다. 지우지 않는다.
- 측정 코드는 산출물이 아니다. 저장소 루트의 `bench/<주제>/` 에 둔다.

## 절차
1. 후보와 비교 기준을 정한다. `$ARGUMENTS` 에 있으면 그것을 쓴다. 없으면 기능 spec 의 미결 기술 선택이나 `docs/tech-spec.md` 의 '가정' 근거에서 고른다.
2. 문서로 답할 수 있는 것(성숙도, 라이선스, 유지 상태, 호환성, 알려진 한계)은 `researcher` 서브에이전트에 맡긴다. 주장마다 출처 URL·확인일을 받는다.
3. 성능처럼 재야 답이 나는 것은 `benchmarker` 서브에이전트에 맡긴다.
   - 넘길 것: 후보, 지표(지연, 처리량, 메모리, 번들 크기 등), 입력, 반복 횟수(5회 이상), 작업 폴더 `bench/<주제>/`
   - 돌려받을 것: 실행 명령, 환경(OS, CPU, 런타임·라이브러리 버전), 후보별 원시 측정값과 중앙값
   - 차이가 반복 간 편차보다 작으면 "차이 없음" 으로 적는다.
4. 템플릿대로 쓴다. 다 채웠으면 `Status: complete`.
5. '시사점' 을 연결한다.
   - 시스템 전체 조사이고 지금 시스템에서 쓰는 기술에 대한 결론이면 `docs/tech-spec.md` 의 '기술 선택과 근거' 표에 행을 추가한다: `| <선택> | <대안> | research/tech.md #<번호> | — |`. 근거가 "가정" 으로 적힌 행이면 그 행의 근거를 바꾼다.
   - 아직 쓰지 않는 기술이면 tech-spec.md 를 고치지 않는다. 도입하려면 `/write-intent` 로 시작하라고 알린다 (구현이 끝나면 `/implement-plan` 이 표에 행을 추가한다).
   - 기능 조사면 research.md 에만 쓴다. `/write-spec` 이 읽고 spec.md '근거' 에 연결한다.
   - 산출물의 승인 상태는 바꾸지 않는다.

## 하지 않는 것
- 한 번만 잰 값이나 출처 없는 주장으로 결론
- `bench/` 밖에 측정용 코드 작성, 프로덕션 자원 대상 측정
- 제품·시장 조사 (`/research-product`)
