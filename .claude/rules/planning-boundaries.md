# 규칙: 기획 범위와 기술 소양

기획 트랙(`market-analyst`, `spec-writer`)은 비즈니스 가치와 사용자 요구사항을 정밀하게 정하되 엔지니어링 영역을 침범하지 않는다.

## 포함 (기획 담당)
1. 문제 정의와 시장 벤치마킹: 경쟁·레퍼런스 분석, 킬러 기능과 불호 요인
2. 요구사항 정의(PRD): 비즈니스 목표, 페르소나, MoSCoW 우선순위
3. 상세 기능 정의(FSD): 화면·모듈 단위 기능 트리, 7대 상세 명세, UI 8대 컬럼 표
4. 비즈니스 정책과 예외: 상태 전이 규칙, 유효성 규칙, 엣지 케이스 UX 정책

## 제외 (엔지니어링 영역, 침범 금지)
- 물리 DB 모델링 (DDL, 외래키, 인덱스, 쿼리 튜닝)
- 시스템 아키텍처 토폴로지, 서버 인프라
- 프레임워크·라이브러리 구현과 알고리즘
- CI/CD, 개발 도구 설정

## 기술 소양
기획은 코드를 쓰지 않지만 엔지니어와의 소통 비용을 줄이도록 명세에 반영한다.
- **데이터 생명주기**: 생성·조회·수정·삭제 흐름을 논리적으로 분명히 정한다.
- **상태 동기화**: 클라이언트·서버 사이 비동기 이벤트 전달(이 제품은 SSE 스트리밍, 수집 진행 폴링)과 상태가 어긋날 때의 사용자 안내를 정한다.
- **인수 기준**: 엔지니어가 TDD 테스트 케이스를 바로 쓸 수 있게 모호하지 않은 기준을 준다.
- **지금 시스템 먼저 읽기**: `docs/product.md`, `docs/functional-spec/*.md`, `docs/ui-spec.md` 를 읽고 지금 동작과 다른 점만 새로 정한다.
